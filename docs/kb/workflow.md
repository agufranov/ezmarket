# Как работаем

## Верстка - 1:1 по макету
- Источник истины - Figma (ссылка в `access.local.md`); при расхождении с ТЗ и скриншотами прав макет.
  Свой дизайн не придумываем, даже «улучшения»: заказчик возвращает такие правки (персиковый круг у карточек
  каталога убрали «по макету» - пришлось вернуть).
- Макеты меняются. Ориентир - самые новые фреймы: например, поддержка - кадры `54:*` (1920x1080 и мобилки),
  а не старые `12:*` и не текст ТЗ (там виджет «по центру высоты», в макете - внизу справа).
- Значения из макета пишем в CSS с номером слоя в комментарии (`// слой 12:1035: 46x46, x 126, y 48`).

## Дешевая сверка с макетом
1. Геометрия слоев - из выгрузки `get_metadata` Figma MCP (XML с x/y/width/height). Один вызов на весь файл,
   результат сохранить и дальше грепать локально - лимит MCP маленький (см. pitfalls.md).
2. Тот же экран на localhost измерить скриптом в браузере (`getBoundingClientRect` относительно панели/виджета)
   и сравнить с координатами слоев. Ждать окончания анимаций (`document.getAnimations()`), иначе размеры масштабированы.
3. Глазами - кадр Figma в соседней вкладке Chrome пользователя (Claude in Chrome), без входа в Figma - только просмотр.
4. Мобилку мерить в iframe нужной ширины (360/440) на той же странице - не трогая размер окна пользователя.
Цвета и тени так не проверить - только глазами.

Сверка целого экрана - скриптами из `tools/mockup-check` (порядок и команды - в README там). Обязательны оба прохода:
**тексты** и **декоративные фигуры** (круги, пятна, кольца, «капли» без текста). Сверка только по текстам пропустила
яркий полукруг в каталоге (в макете прозрачность слоя 60%), круги обложек вдвое больше на мобилке, лишний круг
в баннере и маскот входа на 12 px больше - все это заметил заказчик или нашлось только 28.10.

Тексты: из XML выписать тексты кадра с абсолютными координатами (x/y ребенка в выгрузке - от родителя, складываем
по пути), на странице найти те же тексты (text-узлы и элементы целиком) и сравнить левый край и центр по высоте,
допуск 1-2 px. Шрифт, кегль, цвет текста - в панели свойств Figma (выделить слой по `?node-id=`, прочитать текст панели).
Что так не ловится и как обойти:
- плейсхолдер и значение поля - не текст страницы: ширину поля и отступ текста мерить отдельно (так нашлось поле
  поиска шириной 4 px на мобилке);
- на 1920 у страницы полоса прокрутки - все уезжает на 7 px влево: на время замера `html { scrollbar-width: none }`;
- у детей слоя `Group N` координаты в выгрузке от родителя группы, а не от группы - смещение группы не прибавлять
  (иначе «ошибка» 19 px в бонусах на десктопе);
- текст из нескольких узлов («−{value}%», «Обращение #» + «2041») не находится целиком - проверять руками;
- эмодзи в Windows шире или уже, чем в макете (кнопки «👍 Да») - разница 1-3 px не исправляется.

## Ветки и коммиты
- Работа - в ветке (`feature/...`, `fix/...`). В `main` ветка попадает **одним коммитом**: `git merge --squash <ветка>`,
  потом `git commit` - заголовок о том, что сделано, и имя ветки в скобках, в теле - главное по пунктам. В истории `main`
  и на GitHub - одна запись на ветку, ее коммиты остаются только в ветке. Потом push.
- История `main` до 27.10 (до уведомлений) - перемоткой, по коммиту на шаг; ее не переписываем: нужен был бы force-push
  в публичный `main`, сброс стенда, и сломались бы ссылки на хеши в файлах ревью.
- Коммиты - по шагам, осмысленные, сообщения по-русски: что и зачем; в конце `Co-Authored-By`.
- `package-lock.json` после `npm install` на этой машине меняется (другая версия npm) - не коммитить, откатывать.
- Время коммитов задним числом не подделываем.

## Тесты
- Сервер: e2e по API на настоящей PostgreSQL (`server/test/*.e2e-spec.ts`), гонки проверяются `Promise.all`
  из 10 одинаковых запросов, внешние API (Crypto Pay) - подставным HTTP-сервером в тесте.
- Фронт: `npx tsc --noEmit`, `npx eslint src`, проверочная сборка `NEXT_DIST_DIR=.next-check npx next build`
  (не трогает кэш dev-сервера), экспорт для Pages - с `MSYS_NO_PATHCONV=1` в Git Bash.

## Выкладка на стенд
Стенд - тот же `docker compose` на VPS, проект в `/opt/ezmarket`, настройки в `/opt/ezmarket/.env`
(адрес и доступ - `access.local.md`).
```bash
ssh root@<стенд> "cd /opt/ezmarket && git pull --ff-only && docker compose up -d --build"
```
Миграции применяются при старте контейнера `api`. Перед правкой `.env` на сервере - копия (`.env.bak-ГГГГММДД`);
секреты передавать через stdin (`printf ... | ssh ... "cat >> .env"`), а не в командной строке.
После выкладки: `docker compose logs api` (миграции, ошибки), `curl` по `/`, `/api/orders/limits`, `/api/me`.

## Проверка с нуля по README
Docker Desktop на этой машине не запускается (нет виртуализации для WSL2), поэтому - на VPS, рядом со стендом и не трогая его:
свежий клон с GitHub, отдельный проект, порты только на localhost сервера, смотреть через SSH-туннель.
```bash
ssh root@<стенд> "cd /tmp && git clone -q https://github.com/agufranov/ezmarket.git ezfresh && cd ezfresh &&
  WEB_PORT=127.0.0.1:8090 MAILPIT_PORT=127.0.0.1:8026 docker compose up --build -d"
ssh -N -L 18090:127.0.0.1:8090 -L 18026:127.0.0.1:8026 root@<стенд>   # сайт :18090, Mailpit :18026
ssh root@<стенд> "cd /tmp/ezfresh && docker compose run --rm test && docker compose --profile test down -v --rmi local"
```
Дальше - шаги «Как проверить руками» из README. Код входа - в Mailpit (`/api/v1/messages`, код в теме письма).
27.10: все шаги прошли, нашлась ошибка редиректа nginx (`pitfalls.md`).
