# Фронт: главная, модалки, поддержка, плашка Steam, заказы

## Что сделано (этапы 1-3 из ТЗ)
- Главная: десктоп 1920 / 1440 / 1280 и резиновый 1024-1920, мобилка по макетам 360 и 440 и между ними.
- Шапка: каталог (меню), поиск с хоткеем `/`, подсказки и «ничего не нашли», валюта, профиль, уведомления, пузырь гостя.
- Окно «Вход / Регистрация», шаг «Ввод кода» (без макета, по ТЗ 12.9 - только с сервером).
- Поддержка у виджета: меню-пузыри, частые вопросы, «Написать нам», «Письмо отправлено», карточка «Готово, мы на связи!».
- Демо-состояния на моках: `?auth=1` / `?auth=0`, `?auth=1&notif=0`; текст `error` в форме и email `error@...` - ошибки.

## Поддержка у виджета (кадры 54:*, сверено замерами)
- Виджет: десктоп 64x70, `right: 0`, `bottom: 32px`; внутри полоска 3x22 (8, 25), маскот 46 (10, 15), облачко 21x13 (6, 7).
  Мобилка 58x64, `bottom: 14px`, маскот 42 (8, 14).
- Панели прижаты к низу у виджета: `right: 80px` (64 + зазор 16), `bottom: 32px`.
  Ширины: меню - по контенту (239), частые вопросы 404, «Написать нам» и «Отправлено» 384, «На связи» 420.
- Пузыри меню: высота 52, шаг 62, иконка 40 в 6 px, текст с x = 58, справа 20. Порядок на десктопе: Telegram, Частые вопросы, Написать нам; на мобилке «Написать нам» выше вопросов.
- В «Написать нам» слева всегда значок письма (кнопки «Назад» в макете нет).
- В частых вопросах вопрос сразу под открытым - на 4 px ниже (18 вместо 14; мобилка 16 вместо 12).
- Отдельного «попапа перед Telegram» в макете нет; перед кликом по Telegram виден только экран меню-пузырей.

## Каталог (меню в шапке)
- Персиковый круг 46x46 у нижнего края каждой карточки (слой 12:1035: x 126.39, y 48 при высоте карточки 68) - видна верхняя часть. На мобилке нет.

## Плашка Steam (ТЗ 8.3)
- Лимиты суммы - с сервера (`GET /api/orders/limits`), без API - из `src/config/site.ts`. Поле суммы - целые единицы, на сервер уходит ×100.
- «Оплатить»: гостю - окно входа; иначе заказ (`POST /api/orders` с `Idempotency-Key`) и `POST /orders/:id/pay`.
  Ключ повтора - у попытки вместе с ее заказом и данными формы (`src/services/topUpAttempt.ts`): те же данные и заказ не
  завершен - тот же заказ (двойной клик, повтор после ошибки сети); заказ выполнен/отменен/истек или данные другие - новая
  попытка. Попытка сама помнит свои данные - сброс при правке полей не нужен (он гонялся с `await`, ревью F10).
  Тест - `npm test` (`node --test`, `src/services/topUpAttempt.test.mjs`).
- Оплата открывается **в новом окне**: окно открывается сразу по клику (`about:blank`), ссылка подставляется после ответа;
  при ошибке окно закрывается, при запрете всплывающих окон - переход в этой вкладке.
- Ошибка логина с сервера - красная рамка поля (как у суммы), текст - в `title` и для дикторов. Общих ошибок в макете нет.

## Мои заказы (`/orders`)
- Простая верстка без макета (пользователь сам попросил), токены из `globals.scss`. Плитка «Заказы» в меню профиля ведет сюда.
- Карточки: сумма, логин, дата, цветной статус; у неоплаченного - «Оплатить» (новое окно) и «Отменить»; история статусов раскрывается.
  У `created` без счета (платежка была недоступна) «Оплатить» создает счет через `POST /orders/:id/pay`.
- Пока есть незавершенные заказы - опрос `/api/orders` каждые 5 с (не в скрытой вкладке).
