# Уведомления

Колокольчик в шапке: статусы заказов и бонусы. Код: `server/src/notifications`, триггеры - миграция
`20261027150000_notifications`, тесты - `server/test/notifications.e2e-spec.ts`.

## Когда появляются
- **На каждую смену статуса заказа** - по строке истории статусов (`order_status_history`): ждет оплаты, оплачен,
  выполняется, выполнен, ошибка, отменен, истек. О создании заказа уведомления нет - это не смена статуса.
- **На каждое движение бонусов** - по строке истории бонусов: регистрация, оплата заказа, возврат, кэшбэк.
- Строку `notifications` создает триггер в той же транзакции, что и источник, при любом пути (сервис, воркер, платежка,
  ручной SQL). Источник уникален (`history_id`, `bonus_tx_id`) - ровно одно уведомление на событие: повторы платежки
  и воркера дублей не дают.
- Переход и бонус за него - одна транзакция; кэшбэк и возврат появляются под уведомлением о статусе
  (триггер бонусов срабатывает раньше - имена триггеров по алфавиту).

## Тексты
Собирает API из источника (`texts.ts`) - менять без миграций. Куски `{ t, b? }`: жирное - сумма и бонусы, как в макете.
| Событие | Текст |
|---|---|
| pending / paid / processing | «Заказ на **500 ₽** ждет оплаты», «Оплата получена - пополняем Steam на **500 ₽**», «Пополняем Steam на **500 ₽**» |
| completed / failed | «Steam пополнен на **500 ₽**» (образец из макета), «Не удалось пополнить Steam на **500 ₽**» |
| canceled / expired | «Заказ на **500 ₽** отменен», «Заказ на **500 ₽** не оплачен за 30 минут и закрыт» |
| бонусы | «Начислено **+31 бонус** за покупку» (образец из макета), «Начислено **+100 бонусов** за регистрацию», «Списано **100 бонусов** в оплату заказа», «Вернули **100 бонусов** - заказ не выполнен» |

## Письма
Только об итоге оплаченного заказа (выполнен / ошибка) - в той же транзакции, что и переход (`OrdersWorker.finish`),
через очередь `email_outbox`. **Сбой почты не ломает заказ**: заказ уже выполнен, письмо остается в очереди с ошибкой
и повторяется (до 8 раз). Об отмене, истечении и бонусах писем нет - только колокольчик.

## API
| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/notifications` | `{ unread, items: [{ id, type, text, icon, orderId, read, at }] }` - свои, новые сверху (до 50); 401 |
| POST | `/api/notifications/read` `{ ids }` | `{ unread }`; чужие и несуществующие id не отмечаются; 422 `{ field: "ids" }` |
| POST | `/api/notifications/read-all` | `{ unread: 0 }` |

`type`: `order` | `bonus` (вкладки колокольчика; рефералы и акции сервер пока не шлет). `icon`: `steam` | `coin`.
Счетчик `unread` - по всем непрочитанным (частичный индекс `read_at IS NULL`), не только по 50 в списке.

## Фронт
- Колокольчик (`src/components/sections/HeaderUser.tsx`) - верстка не менялась, меняется источник данных
  (`src/services/notifications.ts`): с API - список и счетчик с сервера, опрос раз в 30 с (не в скрытой вкладке) и при открытии.
  Клик по уведомлению и «Прочитать все» отмечают на сервере, на экране - сразу.
- Ответ, начатый до отметки о прочтении, отбрасывается (номер отметки в `useRef`) - иначе опрос вернул бы непрочитанное.
- Без API (GitHub Pages) - как раньше: моки `src/data/user.ts`, прочитанные - в localStorage, `?notif=0` - «Пока тихо».
