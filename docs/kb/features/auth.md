# Вход по коду из письма

Код `server/src/auth`, тесты `server/test/auth.e2e-spec.ts`.

- Код - 6 цифр (криптостойкий генератор), действует 10 минут, одноразовый. В базе только HMAC-SHA256 с
  `AUTH_CODE_SECRET` (email в составе), в логи не попадает (тело и cookie вырезаны из логов Fastify).
- Новый код не чаще раза в `AUTH_RESEND_SECONDS` (60) и не больше `AUTH_CODES_PER_HOUR` (5) в час на email; новый код гасит прошлые.
- После 5 неверных попыток код сгорает. Неверная попытка сохраняется: ошибка бросается после коммита транзакции.
- Все действия с кодами одного email - под `pg_advisory_xact_lock(hashtext(email))`: параллельные запросы не обойдут лимиты, 10 одновременных проверок - ровно один вход.
- Сессия: 32 случайных байта в httpOnly cookie `ez_session` (SameSite=Lax), в базе SHA-256 токена, 30 дней.
- Регистрация с промокодом: таблица `promo_codes` (EZ100, FRIEND-2026, WELCOME).
- Демо-режим `AUTH_DEMO_CODE=true` (`npm run local`; на стенде выключен с 2026-10-27): код приходит в ответе `/auth/code` (`demoCode`) и подставляется в поле.
  Для проверок через API: `POST /api/auth/code` -> `demoCode` -> `POST /api/auth/verify`.
- Сбой почты не ломает выдачу кода: письмо остается в очереди с ошибкой и повторяется.
- Новый пользователь при первом входе получает +100 бонусов (`BONUS_SIGNUP`, ТЗ 12.8) - в той же транзакции, что и создание; см. [bonuses.md](bonuses.md).
